# App 与 Agent 分层计划

## 1. 目标与范围

将当前架构调整为 `UI → App → Agent / Store`，区分 Kumu 的应用能力与外部 Agent 的协议能力。

本计划基于当前工作区，包含尚未提交的 Pi 接入。实施时保留已有改动，不覆盖或回退它们。

本次只输出计划，不修改业务代码。

### 目标

- UI 负责展示和交互，不直接管理 Agent 连接、归并协议适配事件或写入业务记录。
- App 负责项目、会话、回合、授权状态和持久化协调。
- Agent 层保留现有多协议适配，实现进程通信、能力发现和统一事件输出。
- 区分 Agent 级探测结果与会话级运行状态，避免同 Agent 多会话相互覆盖。
- 为后续应用能力提供入口，不提前实现任务队列、历史搜索等功能。

### 非目标

- 不重写 ACP、Codex、Claude、Pi 协议实现。
- 不引入插件系统、动态加载、通用消息总线或独立后台服务。
- 不拆分 Cargo workspace，不增加应用线程。
- 不在本次实现取消生成、Agent 上下文恢复、任务调度或数据库异步化。
- 不要求所有 Agent 提供相同能力。

## 2. 当前架构核实

| 位置 | 当前职责 | 迁移方向 |
| --- | --- | --- |
| `src/backend/` | 启动配置、连接、探测、协议适配、公共事件 | 改为 `src/agent/`，保留内部结构 |
| `src/agents.rs` | 静态 Agent 注册表 | 合并到 `src/agent/registry.rs` |
| `src/ui/home/mod.rs` | UI 状态、项目和会话流程、连接、回合归并、持久化 | 应用职责迁入 `src/app/`，展示职责留在 UI |
| `src/ui/mod.rs` | 按 Agent 索引的选项目录及当前值 | 拆分 Agent 目录缓存与会话级选项 |
| `src/ui/settings.rs` | 外观设置、Agent 探测及结果缓存 | 探测状态由 App 统一管理，外观设置保留原路径 |
| `src/db.rs` | 同步 SQLite 访问 | 保留存储实现，由 App 协调业务读写 |

需要保留的约束：

- 每个活跃会话一条连接、一个 Agent 子进程；同一连接复用多轮提示词。
- 命令通过无界通道发送；事件目前经 std mpsc、转发线程、futures 通道进入 GPUI。
- 授权结果通过独立 oneshot 通道返回，不进入串行命令队列。
- 连接 ID 用于拒绝旧连接的迟到事件和关闭通知。
- 释放最后一个连接句柄触发后端退出，并释放待处理授权。
- 当前 `TurnBlock::Answer` 包含 GPUI 渲染对象，不能直接作为应用数据搬迁。
- 当前完成回合会保存思考、回答和工具记录；本地历史不等于 Agent 上下文恢复。

## 3. 架构决策

### 3.1 依赖方向

```text
main
 ├── app
 └── ui
      └── app
           ├── agent
           └── db

agent ── stdio ── 外部 Agent 进程
```

- `agent` 不依赖 `app`、`ui` 或 `db`。
- `db` 不依赖 `ui` 或具体 Agent 协议。
- UI 不访问具体协议模块，不持有 `Connection`，不直接调用 `spawn` 或 `probe`。
- UI 可以使用 App 暴露的 Agent 描述和选项值类型，不为隔离名字而复制同构 DTO。
- UI 的字体、主题等展示设置不强行迁入会话应用层。

### 3.2 应用状态的承载方式

第一阶段采用共享 GPUI Entity 承载 App 状态，由主窗口持有，并向设置窗口传递同一 Entity。

- App 可以使用 GPUI 的通知与异步任务机制，不追求本次完全移除框架依赖。
- 项目、会话、回合和事件归并的数据结构不包含窗口、组件或 Markdown 渲染对象。
- UI 订阅应用状态变化并更新视图。
- 不额外引入 App 命令总线；应用方法必须承担状态约束、生命周期或持久化等职责，禁止纯转发包装。
- 不向 UI 返回可长期持有的连接克隆，避免视图引用延长子进程生命周期。

### 3.3 状态归属

| 状态 | 所有者 |
| --- | --- |
| 项目、会话元数据、历史记录 | App / Store |
| 活跃连接、连接身份、回合生命周期 | App |
| 回答文本、思考文本、工具执行状态 | App |
| 待授权请求及用户决策 | App |
| Agent 探测状态与默认目录 | App，按 Agent ID 索引 |
| 活跃会话选项与当前值 | App，按会话 ID 索引，并受连接身份校验保护 |
| 当前选中的会话、展开折叠、滚动、输入草稿 | UI |
| Markdown 渲染对象、弹窗、组件 Entity | UI |
| 协议请求 ID、报文去重、协议级回合终止判断 | Agent |

### 3.4 选项与能力

- Agent 探测结果用于未连接会话的默认展示，不是所有活跃会话的真实状态。
- 活跃连接上报的模型、模式、权限策略、沙箱、推理等级及当前值属于该会话。
- UI 展示时优先使用该会话的实时选项；无实时选项时才使用探测目录作为回退。
- 持久化的用户选择与 Agent 报告的当前值分开保存，避免把探测默认值当作用户选择重新下发。
- 探测请求由 App 去重；多个窗口共享结果。失败后允许重试。
- 保持现有空选项列表表示“不提供此轴”的约定。
- 不预设取消、恢复等尚未实现的能力字段；真正接入时再扩展公共接口。

### 3.5 协议与生命周期保持不变

- 保留 `Cmd`、`Event`、`Connection` 的现有语义，必要时改名，但不在目录迁移中改变行为。
- 保留权限独立通道、强弱引用关系以及连接身份检查。
- 保留现有线程与事件桥接方式；只将其所有者从窗口移到 App。
- 本次不更改数据库结构或自动回放历史。
- 当前错误路径丢弃进行中的回合、正常完成时落盘的行为先保持；改善异常恢复另开任务。

## 4. 目标目录

```text
src/
├── main.rs
├── app/
│   ├── mod.rs          # 共享应用状态、初始化和对外入口
│   ├── session.rs      # 会话流程、连接生命周期、用户选择
│   ├── turn.rs         # 纯数据回合结构、事件归并
│   ├── discovery.rs    # 探测状态、目录缓存、去重
│   └── project.rs      # 项目流程；只有职责足够时再拆文件
├── agent/
│   ├── mod.rs
│   ├── registry.rs
│   ├── config.rs
│   ├── connection.rs
│   ├── event.rs
│   ├── probe.rs
│   ├── acp/
│   ├── codex/
│   ├── claude/
│   └── pi/
├── ui/
├── db.rs
├── theme.rs
└── assets.rs
```

该目录表达职责，不要求先创建空文件。应用方法按完整业务流程组织，不为一两行转发新增模块或方法。

## 5. 实施阶段

### 阶段 0：建立基线

任务：

1. 记录工作区已有修改，确认 Pi 接入作为迁移基线的一部分。
2. 运行 `cargo check`、`cargo test`、`cargo fmt --check`，记录已有失败。
3. 记录主窗口、设置窗口和各 Agent 可用环境的人工验证结果。
4. 为迁移涉及但缺少覆盖的生命周期行为补充测试。

验收：

- 已有失败与迁移新增失败可区分。
- 不将缺少 Agent 二进制或登录凭据误认为代码回归。

### 阶段 1：明确 Agent 层命名

任务：

1. 将 `src/backend/` 移动为 `src/agent/`。
2. 将 `src/agents.rs` 移动为 `src/agent/registry.rs`。
3. 更新模块声明、导入、文档链接和测试引用。
4. 保留协议枚举及四种协议的分发逻辑，不引入 trait 化插件框架。
5. 同步项目架构说明中的路径。

验收：

- 编译及原有测试无新增失败。
- 差异主要是路径和命名，没有协议行为变更。
- 新增同协议 Agent 仍只需注册和启动配置；新增协议仍由枚举分发穷尽检查提示接入点。

### 阶段 2：分离回合数据与渲染状态

任务：

1. 提取 `TurnState`、有序回合块、工具执行和授权数据到 `app/turn.rs`。
2. 从应用数据中移除 `Entity<TextViewState>`、展开状态等 UI 内容。
3. 为回合及其块提供稳定身份，供 UI 关联渲染缓存，不能只用跨回合可能复用的索引。
4. 将回答、思考、工具更新和授权事件的归并逻辑迁入应用数据处理路径。
5. UI 保留 Markdown 缓存，根据内容变化增量追加；内容不再是原文本的延续时重建缓存。
6. 对会话切换、回合完成、会话删除清理相应 UI 缓存。

验收：

- 应用回合数据不依赖 UI 组件。
- 思考、工具、回答顺序不变，工具更新仍修改原块。
- 流式 Markdown 不在每个 token 到达时全量重建。
- 后台会话运行、切换会话后展示及回合完成后的历史展示正确。

### 阶段 3：提取会话应用流程

任务：

1. 建立共享 App Entity，将 Store、项目与会话数据、连接及回合所有权迁入 App。
2. 迁移发送消息、懒创建连接、重放用户选项、事件桥接、回合收尾和持久化流程。
3. 迁移会话创建、删除、改标题及模型等选择的业务约束。
4. 迁移授权决策流程，并保留独立回复通道。
5. 将 `on_acp_event` 改为协议中立的应用事件入口。
6. UI 删除会话前负责确认，App 负责执行；删除后选中相邻会话仍由 UI 处理。
7. UI 的发送入口只提交会话 ID 与文本，应用层负责拒绝空消息或同会话并发发送。

验收：

- `KumuApp` 不持有 Store、Connection 或业务回合状态。
- UI 不直接发送 Agent 命令、处理 Agent 事件或插入消息。
- 删除会话、窗口关闭及连接异常不会遗留授权等待或工作中状态。
- 被替换连接的迟到事件不能修改当前会话。
- 主窗口和设置窗口对共享状态的所有权、关闭行为明确，不形成引用环。

### 阶段 4：统一探测与会话选项

任务：

1. 将主窗口和设置窗口的探测调度及事件桥接迁入 `app/discovery.rs`。
2. 替换 `AgentSessionOptions` 全局混合缓存，建立 Agent 目录与会话实时选项两种状态。
3. 活跃连接的选项事件必须经过会话和连接 ID 校验，不写入其他会话的当前状态。
4. 更新模型、模式、权限策略、沙箱和推理选择器的数据来源。
5. 保持现有权限策略与模式共用协议值的行为，不借迁移引入新的 `SetAccess` 协议语义。
6. 两个窗口共享探测中、成功、失败状态，并支持失败重试。

验收：

- 同一 Agent 的两个会话使用不同模型时，当前值和可选推理等级互不覆盖。
- 主窗口与设置窗口同时需要目录时，不重复探测。
- 旧连接及迟到探测结果不能覆盖活跃会话状态。
- 不支持某个选项轴时，对应控件保持隐藏。

### 阶段 5：回归与文档收尾

任务：

1. 清理迁移完成后不再使用的字段、桥接代码和导入，不保留长期双实现。
2. 检查 `app` 没有具体协议分支，`agent` 没有数据库或 UI 依赖。
3. 更新 README 与 AGENTS.md 的结构、数据流和扩展步骤，保留已有独立修改。
4. 运行完整检查及可执行的人工回归，单独列出未验证项。

验收：

- 本文测试矩阵有明确通过、失败或未验证记录。
- 不再存在指向旧 `backend` 路径的有效代码引用。
- 文档描述与实际线程、回合持久化及会话恢复能力一致。

## 6. 测试矩阵

| 类别 | 必须覆盖 |
| --- | --- |
| 构建 | `cargo check`、`cargo test`、`cargo fmt --check`；区分已有失败 |
| 事件归并 | 文本追加、思考分段、工具原位更新、事件顺序 |
| 授权 | 授权先于工具事件、重复回复、取消、连接销毁释放等待 |
| 会话生命周期 | 首次发送创建连接、多轮复用、删除、异常关闭、旧连接迟到事件 |
| 并发 | 同会话拒绝重复发送，不同会话可独立运行 |
| 持久化 | 用户消息、完成回合、标题和用户选项；保持现有失败路径语义 |
| 选项隔离 | 同 Agent 多会话不同模型、不同推理选项，探测结果不覆盖实时状态 |
| 探测 | 多窗口去重、超时、失败重试、缺少二进制 |
| UI | 会话切换、Markdown 增量渲染、展开折叠、自动滚动、授权入口 |
| 协议回归 | ACP、Codex、Claude、Pi 的现有转换及报文测试 |
| 进程回归 | 有本地环境的 Agent 逐个验证握手、两轮对话、退出；支持授权的验证授权 |

测试优先落在纯回合数据与应用流程边界。需要替代外部进程时沿用现有测试辅助设施，不为测试先建设通用 Agent 插件框架。

## 7. 风险与控制

| 风险 | 控制方式 |
| --- | --- |
| 迁移覆盖未提交的 Pi 实现 | 从当前工作区建立基线，仅移动和更新相关路径 |
| App Entity 被异步任务强引用导致连接不退出 | 异步任务使用弱实体引用，测试窗口关闭与句柄释放 |
| 数据和渲染缓存不同步 | 稳定回合/块身份，明确增量和重建规则 |
| 全局缓存拆分导致初始标签变化 | 明确实时选项、用户选择、探测默认值的优先级并测试 |
| 结构调整混入行为修复 | 每阶段保持现有行为；恢复、取消、数据库异步化另开任务 |
| 新 App 层只形成方法转发 | 以完整业务流程迁移，不复制所有 Agent 命令作为包装 |
| UI 数据读取引入重复数据库扫描 | 保持必要的数据缓存，不在渲染函数内读库 |

## 8. 提交与回退策略

- 按阶段形成可编译、可测试的提交，不将全量迁移集中在一个提交。
- 目录调整与业务状态迁移分开，便于审查协议是否被误改。
- 阶段 2、3、4 内部可拆为更小的可编译提交；中间适配代码在对应阶段结束时删除。
- 本次不改数据库结构，回退代码不需要回滚用户数据。
- 仅回退迁移提交，不对已有未提交工作执行整体恢复或重置。
- 若完整检查存在既有失败，记录基线并验证没有新增失败，不将其标记为全部通过。
